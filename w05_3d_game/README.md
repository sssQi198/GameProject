# 错层 Wrong Floor

浏览器里的第一人称 3D 短篇。教室会一轮轮多出一件不该存在的东西。对准它按 `F` 拍下来，门才会开。第五扇门之后，先看清那双眼睛，再冲向绿色 `EXIT`。

## Run

需要 Node.js 18 或更高。Three.js 和 lil-gui 已经放在 `vendor/`，不用再装依赖。

Windows 上直接双击 `start.bat`，它会启动本地服务器并打开浏览器。玩的时候别关那个黑色窗口。

也可以用终端：

```bash
cd w05_3d_game
node server.js
```

然后打开 [http://127.0.0.1:5173](http://127.0.0.1:5173)。`npm start` 会自动打开浏览器。请用桌面版 Chrome 或 Edge。

不要直接双击 `index.html`。地址栏变成 `C:/...` 或 `file://` 时，浏览器会拦住游戏脚本，标题画面能看到，但按钮点了没反应。页面会提示改用 `start.bat`。

## Controls

| 操作 | 作用 |
| --- | --- |
| `WASD` | 移动 |
| 鼠标 | 环顾。若浏览器不允许锁定指针，按住左键拖动，或用方向键 |
| `Shift` | 冲刺。终局不冲刺会被追上 |
| `E` | 拾起相机 / 拿出 / 收起 |
| `F` | 拍摄（需先拿出相机） |
| `M` | 静音 |
| `Esc` | 暂停。演示中会直接退出 |

拍下当关异常后、以及终局追逐开启时，相机会自动收起，随时可按 `E` 再拿出。已拍中后的关卡间隙、走廊和终局里按 `F` 仍有快门声和后坐，但不会记录异常，也不影响任何判定。

音量滑条在标题画面和暂停 / 结算画面上。浏览器会拦住自动播放，所以声音从点击 **Start** 或 **Watch Demo** 之后才开始。音效全部由 Web Audio 实时合成，没有外部音频文件。

## Watch Demo

标题画面上的 **Watch Demo / 观看演示** 会用这局游戏自己的碰撞、拍照和追逐跑一段缩短流程：跟进教室、拾起相机、拍下第一处异常、出门，然后进入终局追逐和尾声。它不是录像。

演示过程中可以按 `Esc` 或 **Exit Demo**。回到标题后按 **Start** 就是正常人玩，五处异常都会出现。

## 开发时调参

```text
http://127.0.0.1:5173/?debug
```

右上角可以改走路速度、雾、曝光和灯光，也可以打开碰撞框。这些数值在 `src/config.js`。教室和走廊的尺寸在 `src/layout.js`，改关卡前先改那里。

## 五人分工接口

每人优先改 `src/team/` 里自己的文件。标记名和事件在 `src/team/contract.js`。仓库根目录的 README 有给 AI 的任务模板。

| 文件 | 谁改 | 接口 |
| --- | --- | --- |
| `src/team/p1.js` | P1 逻辑与 UI | `hints`、`successLines`、`copy` |
| `src/team/p2.js` | P2 移动与镜头 | `lookHoldSeconds()`、`lookResponsiveness()` |
| `src/team/p3.js` | P3 杂物、灯、窗帘 | `isFlickerDark()`、`extraProps()`、`tick()` |
| `src/team/m1.js` | M1 场景 | `extraColliders()`、`createSceneExtra()` |
| `src/team/m2.js` | M2 人物与异常 | `anomalyFactory`、`createClassmate()`、`createEyes()` |

拍照认 `userData.anomalyLevel`。门、拍照、终局注视通过 `src/team/bus.js` 的 `door`、`photo-ok`、`look-lock` 通知其他人。

## M1 教室模型分支

`feat/m1-classroom-glb-collision` 在不改动 `original-game` 分支的前提下加入了 `assets/models/classroom_m1_v01.glb`。

模型内容与替换范围：

- 只包含**课桌、椅子、教师桌、黑板（含边框、粉笔槽、粉笔和板擦）**，按 6 种材质合并成 6 个网格、720 个盒子、约 8.6k 三角形、约 520 KB；
- 墙体、地面、天花板、门窗、窗帘、灯具和走廊**仍由 `level.js` 程序化生成**，因此第五关门缝异常、第三关窗帘脸、第四关地面脚印等与场景绑定的异常位置不会被遮挡；
- 加载成功后隐藏原来的程序化家具视觉，并用同一套水平碰撞盒继续做玩家碰撞。

家具细节（v2）：桌面板下加了侧撑、四条横撑和桌下书架，学生侧有挡板；椅子由座面框、四条腿、踏脚横杆、两根靠背立柱、三根靠背条和顶帽组成；教师桌有前挡板、侧板、两个抽屉和柜门；黑板带四条边框、粉笔槽、三根粉笔、板擦和两个墙面支架。

异常与新模型的对应关系：

| 关 | 异常 | 对应模型位置 |
| --- | --- | --- |
| 1 | 后排坐着的人影 | `LAYOUT.seat` (-7.85, 4.0)，正好落在第一排第 6 列课桌的椅子上 |
| 2 | 黑板上的字 | 黑板面在 x≈9.90，异常平面在 x=9.84，位于板面前方约 6 cm，不会被边框盖住 |
| 3 | 窗帘内的脸 | 保留程序化窗帘（z≈5.95），异常在 z=5.78 位于布料前方 |
| 4 | 第二台相机 + 脚印 | 地面走道空位 (0.2, -2.75)，不与任何课桌碰撞盒重叠 |
| 5 | 门缝里的错层教室 | 挂在动态 `doorPivot` 上，模型不参与门板，门的开关动画不受影响 |

性能处理：

- 模型从最初 150 个独立节点合并为 6 个材质批次，减少 draw call；
- 文件体积从 5.4 MB 降到约 520 KB，避免加载卡顿；
- 像素比上限从 1.75 降到 1.5，降低高分屏下的填充压力；
- GLB 加载是异步且非阻塞的，失败会自动回退到程序化教室，不影响菜单和主循环。

## M2 同学模型（model_prompts 第一条）

`assets/models/classmate_v01.glb`（约 100 KB，4051 个三角形，14 个网格 + 根节点）按 `docs/model_prompts.md`「同学」「同学 · 面部细化」「同学与木偶 · 拆出关节」三段提示词搭的建模稿。头 1575 三角形（上限 2500）。转台图见 `docs/images/classmate_v01_turnaround.png`（前四格全身，第五格头部、第六格右手特写），脸和手的特写见 `docs/images/classmate_v01_face.png`、`docs/images/classmate_v01_hand.png`。

- 身高 1.75 m，脚底在 y=0，面朝 glTF **+Z**（Blender 里朝 -Y），Y 轴朝上；导出没开 Draco / Meshopt / KTX2，也没有多余扩展。
- 关节层级（glb 里保留父子关系，左右都是先左后右）：

```
Classmate               根节点，extras 里有 legs/shins/feet/arms/forearms/hands/body/head
├─ Classmate_Body       躯干、外套、领口、书包、脖子，原点在脚底
│  └─ Classmate_Head    y=1.535，头和头发
├─ Classmate_Leg_L      (-0.090, 0, 0.895)，只有大腿
│  └─ Classmate_Shin_L  膝下 0.45 → y=0.445，只有小腿
│     └─ Classmate_Foot_L  踝下 0.35 → y=0.095，只有鞋
├─ Classmate_Arm_L      (-0.190, 0, 1.400)，外张 13°，只有上臂
│  └─ Classmate_Forearm_L  沿袖 0.30 m → (∓0.257, 0, 1.108)
│     └─ Classmate_Hand_L  再 0.25 m → (∓0.314, 0, 0.864)，手掌 + 手五指
└─ …_R 同上，x 取正
```

  每段都是封闭网格，接缝在关节处并互相插进 5 mm，静止姿势旋转为零就是现在这副站姿；膝、肘没有球，转大角度时沿接缝张开，肩、髋各有一对球跟着身体。
- 空物体 `Classmate` 是根节点，extras 写的是部件名数组（先左后右），每个网格另有 `role`（body/head/leg/shin/foot/arm/forearm/hand）。
- 材质 11 个，全部哑光：`Cloth_Navy` #252a3a、`Cloth_Trim` #1a1e2a、`Pants_Charcoal` #1d2026、`Skin_Warm` #cba57f、`Skin_Shadow` #b18f6e、`Hair_Black` #17130f、`Bag_Brown` #33291f、`Collar_Pale` #a8a294、`Eye_White` #7a7166、`Eye_Dark` #2b2018、`Face_Shadow` #231a15。
- 肤色 `#cba57f`（暖偏黄），**和第一段提示词的「skin dark warm gray-brown」不一致**——按后续要求换成了黄种人肤色，夜里的阴影改由眼窝、眉弓和刘海压出来。
- 头部（面部细化那版）：窄下颌、小下巴、低颧骨、浅眉弓（1.658 处往前顶 1 mm）、太阳穴微凹；16 边放样，下巴到头顶 20 圈截面。
  - 眼睛是疲惫的杏仁形，上缘平、内角低 2 mm，厚上眼睑；虹膜 `Eye_Dark` #2b2018 平顶压在上眼睑下，宽度约占半只眼；眼白 `Eye_White` #7a7166，没有睫毛和高光。
  - 眉毛内端粗、外端细，内端高约 2 mm；鼻梁从两眉之间起，鼻头软，两个浅鼻孔；嘴闭着，薄上唇 + 稍厚下唇，颜色 #231a15。
  - 眉下、鼻下、下唇下各有一片 `Skin_Shadow` 软阴影（压暗 12%）。
  - 耳朵 4.2 cm，上半截和头发齐平；刘海是三撮几毫米的碎发，发际线不是一条直线。
  - 五官薄片全部用 Shrinkwrap 沿 +Y 投影贴到头部表面（3～4.6 mm 分层），低面数也不会悬空。
- 手部：手掌 + 四根手指（食指 6.0 / 中指 6.6 / 无名指 6.2 / 小指 5.2 cm）+ 拇指，截面 6 边形、指尖收细；整只手在 `Classmate_Hand_*` 里，跟着腕关节转。
- 提示词写的是「单网格」，但同一份文档又要求按髋、肩拆成可转动物体，所以这里直接建成带父子关系的分段网格——拆分和旋转中心都是建模时定好的。
- 着色用 `shade_smooth_by_angle(86°)`：盒子棱角保持硬边，头部和四肢的过渡不再被切成一条条亮带。

两个 Blender 脚本可重复执行（每次重建 Classmate 集合，再覆盖 glb / 转台图）。工作区不允许 Blender 直接写文件时会退回系统临时目录并打印路径，拷回仓库即可。

| 脚本 | 作用 |
| --- | --- |
| `tools/build_classmate.py` | 程序化建模 + 导出 `assets/models/classmate_v01.glb` |
| `tools/render_classmate_sheet.py` | 六格转台图（临时棚灯，渲完删掉并还原场景） |
| `tools/headless_run.py` | 没有 MCP 插件时用 `blender -b --factory-startup -P tools/headless_run.py` 跑完整流程 |

## 第五关 · 眼睛模型（model_prompts 第三条）

`assets/models/eyes_v01.glb`（约 18 KB，880 三角，2 个网格 + 根节点）按 `docs/model_prompts.md`「第五关 · 眼睛」搭的建模稿：只有两颗红色发光眼球，没有眼睑、瞳孔、脸和身体。

- 每只直径 0.174 m（半径 0.087），球心相距 0.38 m（x = ±0.19），和 `anomalies.js` 里的 `EYE_R` / `EYE_DX` 一致。
- 20 段经线 × 12 圈纬线（含两极）的 UV 球，每只 440 三角（极低面数）；两只是各自独立的网格，节点名 `Eye_L` / `Eye_R`，根节点 `Eyes`。
- 材质 `Eye_Glow`：底色纯黑、Roughness 1、Metallic 0、自发光 **#ff2030**（emissiveFactor 按线性空间写入）。没有贴图、UV、Draco / Meshopt / 其他扩展，单面渲染。
- 局部原点在**两眼连线中点**，每只球的原点在自己球心上；根节点 extras 写了 `eyes`、`diameter_m`、`spacing_m`、`eye_y_m`（2.42 m，第 5 关的球心高度）、`up_axis`。进游戏时整对放在 `(EYE_CX, 2.42, -5.981)`，正好和原来的程序化球重合。

接入方式（`src/anomalies.js` 的 `createFleshWall()`）：先建程序化球，`eyes_v01.glb` 载入成功后再换掉；两颗球统一改用原来的 `MeshBasicMaterial`（`toneMapped: false`），因为 ACES 会把 StandardMaterial 的红压灰，而且拍后淡出改的就是这个材质的颜色。光晕、红色点光、拍照命中球、心跳缩放、缓慢扫视和 1.6 秒淡出逻辑都没动。载入失败时保留程序化球，页面 `<body data-eyes-model="glb|fallback">` 可以看走的是哪条路。

预览图 `docs/images/eyes_v01_turnaround.png` 是 2×2：正面一对（量到直径 168.0 px / 眼距 368.0 px，理论 168.7 / 368.5，误差 0.5% 以内）、3/4 透视、单眼特写、线框。辉光只在预览里加，不进 glb。

验证：

```text
node _probe/eyes_asset.mjs   # glb 结构、尺寸、#ff2030、three.js 能否加载
node _probe/eyes.mjs         # 第 5 关两只眼的位置 / 不凸出开口 / 拍后淡出
```

重建（Blender 5.2；脚本可重复执行，先建模型再出图）：

```text
blender -b --factory-startup -P tools/build_eyes.py -P tools/render_eyes_sheet.py
```

## 第五关 · 黑色巨脸模型（model_prompts 第四条）

`assets/models/face_v01.glb`（约 128 KB，3744 三角，1 个网格 + 根节点）按 `docs/model_prompts.md`「第五关 · 黑色巨脸」搭的建模稿：一张压扁的巨大黑人脸，没有眼睛、眼窝、牙齿、耳朵和头发。规格和接口细节见 `docs/face_v01_spec.md`。

- 尺寸 1.15 × 1.70 × 0.040 m（宽 × 高 × 厚），原点在包围盒中心；Blender 里正面朝 -Y，导出后正面朝 +Z。摆到 `(0, 2.45, -5.9635)` 时最前面正好是 `z = -5.945`，比眼睛前极还靠里，不凸出裂缝开口。
- 拓扑：按头形参数化的四边形网格（31 列 × 55 行）+ 156 个三角形的背板；前表面平滑、侧壁平直；非流形边 0、边界边 0、孤立点 0。
- 五官全部由 `relief(x, z)` 一处算出：眉弓（两条带弧度的眉棱 + 眉下浅沟）、鼻根 / 鼻梁 / 鼻尖 / 鼻翼 / 鼻底、颧骨与颧弓下沟、下颌角 → 下颌体 → 下巴、微垂的嘴缝与上下唇、太阳穴凹陷、鼻侧沟和法令纹。整段起伏线性压进 4 cm，轮廓边留 4 mm 侧壁。
- 材质 `Face_Charcoal`：底色 `#0d0809`，Roughness 1.0、Metallic 0、单面；顶点色 `Col` 是 0.30–1.00 的乘数（高度 + 迎光法线 + 五官 + 空腔），乘出来正好落在规划书说的 `0x030202 … 0x0d0809` 几级近黑。glTF 里是 `baseColorFactor × COLOR_0`，顶点色丢了也只会更黑，不会变白。另外带一套正投影 UV，以后要贴图不用重新展开。
- 提示词要 1.7 m 高，比 `docs/level5_eyes_plan.md` 里的 `FACE_H = 1.55` 高 15 cm：顶到世界 y = 3.30，而裂缝竖直臂只到 3.13，多出来的 17 cm 被上方的墙带挡住。
- 预览图 `docs/images/face_v01_turnaround.png` 是 2×3：上排是游戏里的样子（正面 / 3/4）和鼻子特写，下排是素模正面 / 3/4 和线框。素模正视图量到 378 × 558 px，换算 1.152 × 1.700 m（理论 377.4 × 558.0）。
- 接进游戏：`anomalies.js` 的 `createFleshWall()` 先建程序化的几块板，`face_v01.glb` 载入成功后再换掉；材质换成 `MeshBasicMaterial({ vertexColors: true, toneMapped: false, fog: false })`（规划书 §4 步骤 3：脸不参与光照，也不被 ACES 压色）。载入失败保留程序化脸，页面 `<body data-face-model="glb|fallback">` 可以看走的是哪条路。

重建（Blender 5.2；脚本可重复执行，先建模型再出图）：

```text
blender -b --factory-startup -P tools/build_face.py -P tools/render_face_sheet.py
```

## 第五关 · 咧嘴的牙模型（model_prompts 第五条）

`assets/models/teeth_v01.glb`（约 61 KB，1972 三角，1 个网格 + 根节点）按 `docs/model_prompts.md`「第五关 · 咧嘴的牙」搭的建模稿：17 颗牙单独浮着，没有嘴唇、牙龈、脸和眼睛。规格和接口细节见 `docs/teeth_v01_spec.md`。

- 尺寸 0.9000 × 0.4523 × 0.0587 m（宽 × 高 × 厚），原点在包围盒中心；Blender 里正面朝 -Y，导出后正面朝 +Z。

## 第五轮：终局镜头自动转回逃跑方向

终局原本是"镜头被强迫转去看身后的怪物 → 交还操作 → 玩家自己用鼠标转回来 → 再跑"。这一轮把中间那步交给程序：

- `game.js` 的 `beginChase()` 不再直接进入 `finaleChase`，而是先把镜头交给 `player.beginAutoTurn(ESCAPE_YAW, 0)`，用和强制注视同一套指数收敛（`lookResponsiveness()` = 7）把朝向拧回 +X —— 也就是走廊尽头 EXIT 那一头。180° 实测约 0.73 秒（44 帧），走短弧、误差单调收敛。
- 转到位（差 1° 以内）才 `finishTurnBack()`：这时才 `setControl(true)`、`hud.setChase(true)`、发 `lookUnlock`。`finaleLook` 期间怪物本来就不动（`stepEntity` 只在 `updateChase` 里调），所以这段戏是免费的反应时间，不算罚站。
- 转向期间 `player.js` 每帧清掉累加的鼠标增量，交还操作的那一瞬间不会甩一下。
- 只给角度不给目标点：正后方正好差 180°，用目标点算方向会左右不定（`lerpAngle` 在 ±π 处取哪边取决于末位误差）。
- 顺手删掉了提示文案 `copy.turnAndSprint`（"反方向。按住 Shift。"）—— 现在不需要转身，`p1.js` 里这个键也一并删掉。调试跳转 `finalechase` 的朝向和提示同步改成"面朝 EXIT、一路往前跑"。

自检脚本 `_probe/turnback.mjs`（纯逻辑，不需要 DOM）：断言注视能到位、转向自己结束且 yaw 精确落在 −π/2、俯仰归零、误差单调收敛、耗时在 0.35–1.2 秒、转完的 forward 就是 +X、转向期间丢弃鼠标增量、`reset()` 会清掉该状态。

## 第六轮：起跑提示与追逐段灯光

转回逃跑方向的那一帧做了三件事（都是纯表现层，不碰状态机）：

- **屏幕正中「快跑！」**：`#chase-flash`，`hud.flashChase()` 加 `.on` 触发一条 **纯 CSS** 动画（1.7 秒：0.14 秒放大淡入 → 保持全亮到 1.05 秒 → 0.65 秒淡出），`forwards` 停在 `opacity:0`。不逐帧写 `style.opacity`，动画全在合成线程上，追逐开始那一下不掉帧。重播靠 `remove('on') → 读一次 offsetWidth → add('on')` 强制重启；`setChase(false)`（被抓/重开）把 `.on` 摘掉，不会残留半透明的字。
- **顶部那行改成常驻的「按住 Shift 冲刺」**：原来那句"反方向 · 按住 Shift · EXIT"随自动转向一起没了，现在 `#chase` 只留操作提示，从交还操作起一直挂到追逐结束，`setChase()` 统一控制显隐。
- 字号 `260u`（1744 宽的窗口上约 97.5 px），红色 `#ff2a26` 加三层红色 text-shadow；`z-index:2` 压在准星上面（准星那个点正好落在字的中间）。`prefers-reduced-motion` 时换成不缩放的 `chase-flash-flat`。

**走廊灯池**（`src/hallglow.js`，纯数值模块，不进 THREE）：

- 平时走廊灯半径 14 米、10 米一盏，光摊平成一整条亮度。追逐时把半径收到 `CONFIG.hallPoolRadius = 5.5` 米 —— 比「两灯中点到灯」的距离 √(5² + 2.55²) ≈ 5.6 米还小，所以两灯正中间**一盏灯的光都拿不到**，只剩环境光；灯正下方拿满。半径边缘是 three 自己的平滑收尾，不会切出硬边。
- 亮度靠 `CONFIG.hallPoolGain = 2`。实测：地面照度灯下 10.07、平时 5.61（1.8 倍），中点 0.00（占灯下的 5.2%，即几乎只剩环境光）；换算成像素，墙面上灯下 175 对平时 129、离灯 3 米只剩 44、5 米 6 —— 暗带从离灯 3.1 米开始，在 10 米间距里约 2.6 米是明显更暗的。
- 只改强度、距离和灯管自发光，**灯的数量始终保持 10 盏**：增删点光源会让 three 重编译着色器，进追逐那一下会顿一下。
- 其中两盏在抖：`HALL_FLICKER_X = [10, 30]`（跑起来正好先后经过）。每 3.6 秒抖一次，窗口 0.55 秒切成 5 格、每格 0.11 秒整段熄灭，每盏按自己的格子表断两次（两次之间亮一格）——单帧黑一下人眼看不见，必须连续 3 帧以上才像"灯管接触不良"。整段时间里只有约 5% 是灭的，但抖动窗口里近一半是灭的。不用 `Math.random`：逐帧随机只会变成噪点，看不出节拍。
- `lightFlash()` 每帧在 `updateLights()` 之后跑，追逐段每帧都会把强度/距离/自发光重新写回，爆闪不会留下僵掉的走廊灯数值；退出追逐走 `else` 分支还原（calm 时 1.6 倍）。

自检脚本 `_probe/hallglow.mjs`（纯数值，不需要 DOM）：断言 10 盏灯、闪烁灯在跑道范围内、灯池半径小于中点到灯的距离、中点照度约等于 0、灯下/灯间反差 > 8:1、暗区起始位置、每次灭 ≥ 3 帧且是"闪两下"、两盏不同步、其余灯恒定、闪烁曲线恒在 (0, 1]；`--profile` 还会打一张墙面/地面的 ACES 亮度表，用来看"到底多亮多暗"。

## 第七轮：追逐音效与身后熄灯

上一轮只解决了「看得见」，这段追逐的耳朵里还是空的：怪物**完全没声音**（`npcFootstep()` 在 `npcState !== 'walking'` 时直接 return，而追人的是另一个 `entity`），心跳与压力无关，起跑那一下也没有冲击。这一轮补三件事，全部是可听/可见的表现层，不改状态机、不加设置开关。

**A1 怪物脚步**（`audio.js` 的 `monsterStep()`，`game.js` 每帧调用）

- 一段 0.17 秒 lowpass 150Hz 的噪声给体重，叠一层 0.045 秒 bandpass 1100Hz 的「爪尖轻碰」给方位 —— 只有低频的话小喇叭听不出来。
- 音量 `(1 − d/14)^1.35 × 0.5`：2 米处 0.41、9 米处 0.12、14 米以外直接不发声（不在地板下造一个听不见的假声源）。实测近/远比约 3.4 倍，跑起来能听出它在靠近还是被甩开。
- 步幅 1.5 米、速度 4.45 m/s ⇒ 约 **2.9 步/秒**。累积的是**走过的距离**而不是帧数，掉到 30fps 步频不变（`_probe/chasefeel.mjs` 里两种帧率都是 29 步/10 秒）。
- 每步过一个 `StereoPanner`，左右脚在 ±0.28 交替；噪声从缓冲里随机偏移起播（同一段噪声反复从 0 秒开始会像电子节拍器）。

**A2 心跳与低频跟随压力**（`setTension()`）

- `game.js` 的 `updatePresentation()` 把本来只喂给 `#danger` 的那个值（`1 − (d − entityCatch)/6`）同时喂给 `setTension()`。心跳周期 **0.62 → 0.40 秒**（95 → 144 bpm），单下增益 **0.55 → 0.80**，第二下打 78%（不对称才像心跳而不是鼓点）。
- 追逐时 drone 基音 48 → 58Hz，三角波同步 ×1.5。48Hz 在笔记本喇叭上基本听不见，所以真正起作用的是 72/87Hz 那一层和心跳本身。
- `setTension()` 只在 `mood === 'chase'` 时改频率：退出追逐后 `setMood('calm')` 的 196Hz 不会被下一帧的 `setTension(0)` 打回去。变化 < 2% 直接跳过，不每帧重排自动化曲线。

**A3 抽空 + 起跑 stinger**

- 自动转身那 0.73 秒 `duckAmbient(true)` 把环境低频从 0.03 抽到 **0.004**（真空），交还操作那一帧 `duckAmbient(false)` 还原并同时 `stinger()`：92 → 34Hz 的下潜（0.45 秒）+ 300 → 2600Hz 的噪声扫 + 两根很轻的 660/990Hz 三角波。
- 和 `hud.flashChase()` 同一帧发出，所以「快跑！」出现的那一下同时有声音落地。重复调用 `duckAmbient(true)` 不会重复排队参数自动化。

**A5 + S1 身后的灯永久熄灭**

- 追逐中 `playerX > lampX + 1.2`（`hallglow.hallLampPassed()`）就把那盏灯写成 `intensity = 0`、灯管自发光 0，并记进 `level.hallDead`（`reset()` 清空）。灯**不删**，只灭 —— 灯数还是 10 盏，不会触发着色器重编译。
- 熄灭时 `audio.lampDeath(pan)`：128 → 70Hz 的方波「嗡」+ 一点玻璃/电流噪声，声像由 `hallLampPan()` 按灯与玩家的横向差给（灯在身后 ⇒ 全在左侧或正中）。
- 两道静音门槛，避免起跑那一下糊成一串：① 进追逐的第一帧把「起跑时已经在身后」的灯（本关是 x = −30/−20/−10 三盏）静音处理掉；② 只给身后 8 米内的灯配声音，更远的灭在雾里，本来也看不见。
- 走廊变成「前方有灯、身后全黑」，跑起来能感到自己在把整条走廊一盏盏吃掉。

自检脚本 `_probe/chasefeel.mjs`（假 `AudioContext` 记录所有节点与参数自动化，不需要浏览器）：断言心跳两档周期/增益、第二下更轻、drone 48→58、stinger 的 92→34Hz 与噪声扫、抽空与还原值、脚步的距离衰减与 14 米静音、左右脚 ±0.28、噪声偏移不重复、步频与帧率无关、灯灭方波与声像、`hallLampPassed/hallLampPan` 边界、以及把 `updateLights()` 的追逐分支照抄一遍跑完整条走廊（6 声、全灭、前方留灯、一帧跨 38 米不补响）。

## 第八轮：追逐音乐与怪物嘶吼

> **已下线（第十四轮）**：本节到第十三轮描述的「嘶吼」与「追逐音乐」两套东西已整套删除——代码、素材、Dev 面板试听、探针一起撤掉，`src/chasemusic.js` 不再存在。下文原样保留，是重做这块时最省事的参考：哪些数试过、哪些坑踩过（尤其第九轮的频段分析）。

第七轮解决了「有声音」，但整段追逐的音乐还是原来那首循环曲 —— 它只是在跑起来时从 0.18 抬到 0.23（约 +2dB），三五秒之后就习惯了。这一轮不再塞第二个 mp3，而是**在引擎里现场合成一层只属于追逐的音乐**，让它跟着怪物的距离变快、变刺；原曲反而压到 0.06，退到后面当底噪。

**M1 节拍（`chasemusic.js` 的 `chaseBeatPlan()`）**

- 一拍的长度从压力 0 的 **0.40 秒（150bpm）** 缩到压力 1 的 **0.32 秒（187bpm）** —— 越近越快，是「它在追上来」最直接的听觉信号。
- 1、3 拍低鼓（正弦 120 → 55Hz 下滑），每 8 拍的第一下更重；2、4 拍加一记 bandpass 2.4kHz 的金属敲，但**压力过半才进**：前半段不吵，后半段才开始刺。
- 每 8 拍一次噪声扫频（400 → 3000Hz），正好收在下一小节第一拍上；同样有 0.4 的压力门槛，否则每三秒扫一次会腻。

**M2 不谐簇 / M3 颤弓 / M5 轰鸣（三层常驻）**

- 三支 saw 定在 **110 / 116.5 / 155.6Hz** —— 故意不是纯五度，慢速时是一团嗡，快起来才听得出拍频。群奏低通随压力从 600 → 1400Hz 开亮，失谐从 ±6 拉到 ±14 音分（三支不同向，同向只会跑调不会晃）。
- 1.4kHz 窄带噪声被 11 → 15Hz 的 LFO 切，是「弦乐颤弓」那种紧张，不是电锯。
- 楼体轰鸣：32Hz 三角 + 90Hz 低通噪声，层音量 0.05 → 0.12。32Hz 在笔记本喇叭上听不见，真正起作用的是它的谐波和那层噪声。

**调度器：0.15 秒 lookahead，按 `ctx.currentTime` 排**

- 每帧只看「未来 0.15 秒内有没有拍子要落地」，有就按时间戳排给 Web Audio，**不按帧计数**。掉到 30fps 拍数不变（`_probe/chasemusic.mjs` 里 30fps 与 60fps 都是 8 下、落拍时刻差 0ms）。
- 切后台 30 秒回来只对齐一拍，不会一次补几十拍（`resyncGap: 0.5`）。
- 压力变化小于 2% 直接跳过，不每帧往音频线程写参数自动化。

**M4 与起跑对齐**

- `finishTurnBack()` 里 `startChaseMusic()` 和 `stinger()`、`flashChase()` 是**同一帧**：真空抽完 → 92 → 34Hz 下潜 + 「快跑！」+ 节拍层第一拍同时落地，起跑那一下才有重量。
- 离开追逐（`setMood()` 收到非 `chase`、被抓、通关、重开一局）就 `stop()`：常驻节点全部停掉、输出增益放掉，再进一次能重新从第 0 拍起。

**怪物嘶吼（`audio.js` 的 `roar(vol, pan)`）**

- 一条 68 → 46Hz 的 saw 当喉音，被 5.5Hz 正弦做 ±18 音分的颤音（不机械）；两个高 Q 共振峰（420 / 1150Hz）塑出喉咙的「兽味」；17Hz saw 做粗糙调幅（声带的撕裂感）；外加一层 2.6k → 1.7k 的带通嘶声。总长 1.25 秒。
- 三个触发点，音量分级，都不盖住别的信息：
  - 镜头被迫看向那张脸的那一帧（`beginFinale()`）吼 **0.85**。吼声 1.25 秒，强制注视也是 1.25 秒（`lookHoldSeconds()`），所以它正好收干净、下一帧才进 0.73 秒完全无声的真空 —— 节奏是「吼完 → 死寂 → 快跑！」；
  - 追逐中靠近到 **4.6 米**以内吼 **0.5–1.0**（越近越响），声像按怪物与玩家的横向差给；吼完要有 4.5 秒冷却、且必须先退到 6.2 米外才会再吼 —— 用回滞，避免在 4.6 米边缘上一帧一吼；
  - 被咬住那一刻（`lose()`）吼 **1.1**，压过其它所有声音。
- 峰值 `0.62 × vol`（vol 上限 1.2），比 stinger 的 0.72 低一档：嘶吼是用来「顶一下」的，不是用来抢起跑的。

自检脚本 `_probe/chasemusic.mjs`（假 Web Audio，和 `chasefeel.mjs` 共用 `_probe/fakeaudio.mjs`）：断言节拍表的两档周期与超范围夹取、低鼓/金属敲/上升音的落拍与压力门槛、常驻三层的频率/滤波/LFO、第一拍贴帧、压力 0 与 1 的拍距 0.80 / 0.64 秒、30fps 与 60fps 一致、时间跳 30 秒只补一拍、参数 <2% 跳过、`musicGain` 0.06 / 0.18、离开追逐拆干净并能重开、以及嘶吼的 68 → 46Hz、共振峰、颤音 ±18 音分、17Hz 粗糙层、嘶声、三档峰值与 `roar(0)` 不建节点。目前 `_probe/` 里 14 个脚本 + 1 个共用的假音频模块，全部 exit 0。

> 第九轮按试听反馈重做了频段，本节里的 **0.06 / 0.62 / 68 → 46Hz** 三个数已被覆盖，请看下一节。

## 第九轮：把「听不见」修掉 —— 中频补齐 + 吼声让开音乐

第八轮做完试听，反馈是「吼声不明显，而且音乐好像还是游戏正常音乐没有变」。**代码确实在跑**（`game.js:263` 每帧 `audio.update()`、`finishTurnBack()` 里 `startChaseMusic()`、`devtools.js` 的「终局·追逐」也会起节拍层），问题在**频段**：

| 层 | 第八轮的主能量 | 笔记本/手机小喇叭 |
|---|---|---|
| 嘶吼 | 68 → 46Hz 的基频，被 420 / 1150Hz 的**高 Q** 带通各切一刀 | 200Hz 以下基本放不出来，切完只剩「闷响」 |
| 低鼓 | 120 → 55Hz | 同上 |
| 不谐簇 | 110 / 116.5 / 155.6Hz 过 600Hz 低通 | 同上 |
| 轰鸣 | 32Hz | 本来就没指望它 |
| 原曲 mp3 | 全频段、母带压过 | **全场最响的其实是它** |

也就是说：新写的东西全在低频，原曲是全频段 —— 小喇叭上听到的自然还是「正常音乐」。这一轮就是把中频补回来，并且让吼声把音乐压下去。

**M6 短和弦 + 中频抬升（`chasemusic.js`）**

| 项 | 第八轮 | 第九轮 | 理由 |
|---|---|---|---|
| 不谐簇低通 | 600 → 1400Hz | **700 → 1900Hz** | 600Hz 在小喇叭上等于没声 |
| 不谐簇层音量 | 0.05 | **0.07** | +3dB |
| 金属敲 | 0.09，Q 9 @ 2400Hz | **0.16，Q 3.5** | Q 9 的带宽只有 267Hz，放宽到 700Hz 才听得见「叮」 |
| 颤弓 | 0.028 / 深度 0.026 | **0.05 / 0.045** | 颤弓是在调幅，深度必须小于层音量 |
| 上升音峰值 | 0.12 | **0.20** | 一句结尾那口气 |
| **M6 短和弦** | 无 | **2、4 拍 220 / 233.1 / 311.1Hz 三支 saw，0.1 秒** | 200–1k 原本是空的，而这是小喇叭唯一放得出的频段 |
| 原曲 `musicGain`（追逐） | 0.06 | **0.035**（比平时 0.18 低 14dB） | 原曲不压狠一点，「换了音乐」永远是一耳朵听不出来的事 |

**沿用**：拍长 0.40 → 0.32 秒、压力 0.5 才进金属敲、每 8 拍一次扫频、0.15 秒 lookahead、30/60fps 一致 —— 这些第八轮的东西没动，探针照旧守着。

**音乐让开闸 `musicDuck`（`audio.js`）**

- 新加一个 `GainNode` 夹在 `musicGain`（原曲）与 `ChaseMusic` 之间、`master` 之前：两条音乐都从这道闸过。
- `duckMusic(depth = 0.5, hold = 0.9)`：`setTargetAtTime(0.5, now, 0.04)` 快速落下 → `setTargetAtTime(1, now + hold, 0.25)` 自己涨回来。**不碰 `setMood()` 排的 `musicGain` 目标值**，所以两种自动化互不打架。
- 为什么要单独一条：吼声走 `out(pan)` → `master`，`duckAmbient()` 只压 `ambientGain`，压不到音乐；没有这道闸，吼得再响也只是「音乐里多了点声音」。

**嘶吼重做（`audio.js` 的 `roar(vol, pan)`）**

| 层 | 第八轮 | 第九轮 |
|---|---|---|
| 喉 | saw 68 → 46Hz | saw **96 → 62Hz**（全部上移一个八度的一半） |
| 咆 | 无 | saw **190 → 132Hz**，小喇叭上真正听到的「主体」 |
| 峰 | 420 Q5 / 1150 Q7 | **520 Q4 / 1300 Q6** |
| 肉 | 无 | **2400Hz 低通 ×0.35**，把锯齿整串谐波留下来当「厚度」 |
| 权重 | 两个带通各 1.0 | 低通 0.35 / 520Hz 0.62 / 1300Hz 0.78 —— 能量往中频倾斜 |
| 糙 | 17Hz 调幅 + 嘶声 | 保留，另加 **750Hz 宽带噪声（Q1.1），峰值 0.5** 随 17Hz 一起被切 |
| 颤音 | 5.5Hz ±18 音分 | 5.5Hz **±22 音分**，两条嗓子共用同一个 LFO |
| 峰值 / 时长 | 0.62 × vol，1.25 秒 | **0.95 × vol，1.5 秒**（嘶声 0.28） |
| 副作用 | 无 | 起吼时 **`duckMusic(0.5, 0.85)`** |

三处触发点的音量：`beginFinale()` 0.85 → **0.95**；追逐 4.6 米内 0.5–1.0 → **0.6–1.05**；被咬 1.1 不变（上限 1.2，`1.14` 是夹取后的峰值）。

**为什么是这些数（`_tools/roar_band.py`）**：探针只能证明「节点接对了」，证明不了「小喇叭放得出来」。这个脚本用和 Web Audio 同一套 RBJ 公式算出每条路径的 `|H(f)|²`，再把锯齿谐波与噪声谱加权求和：

| | 第八轮 | 第九轮 |
|---|---|---|
| 总能量 | 0.028 | 0.122（**+6.5dB**） |
| 300-3000Hz（小喇叭有效段）绝对能量 | 0.023 | 0.060（**+4.1dB**） |
| 300-800Hz 的来源 | 420Hz 窄带通挑出的第 6/7 次谐波，一条细线 | 96/190Hz 的第 2~8 次谐波，成片 |
| <300Hz 占比 | 14% | 50%（耳机上的「胸口」，小喇叭放不出，属于白给的厚度） |

顺带解释了为什么第八轮「不像吼」：**两个 Q5/Q7 的窄带通把 68Hz 基频整个滤没了**（68Hz 在 420Hz 带通外 6 个八度），活下来的只有一条 420Hz 的细线和一层 2kHz 噪声 —— 听起来像气声，不像嗓子。

**Dev 面板加了「音频试听」三个按钮**（`index.html` 的 `data-dev-audio`，逻辑在 `devtools.js`）：`嘶吼` / `追逐音乐` / `恢复原曲`。只碰音频、不动游戏状态，所以不用真的跑完一关就能验这两件事 —— 之前「听不出来」有一半原因是只能在追逐那十几秒里听。

自检脚本 `_probe/chasemusic.mjs` 同步改到新数值：新增 M6 短和弦的落拍与「掐一下就走」、短和弦从第一拍就进（和金属敲的门槛不同）、不谐簇最亮 ≥1800Hz、原曲 0.035、原曲与节拍层都接在 `musicDuck` 上、吼声同时把音乐让开一半（0.5 → 1）、两条嗓子共用颤音 LFO（靠 `fakeaudio.mjs` 新加的 `dests` 数组记多个连接目标）、三条路的权重 0.35/0.62/0.78 与 750Hz 噪声的 0.5 峰值，以及新的 96 → 62Hz / 190 → 132Hz / 520 / 1300 / 2400 / 750 和 0.95 峰值。

**验证**：`node --check` 五个改动文件 + `_probe/` 全部 14 个脚本 exit 0。探针只能证明「排出来的音频图是对的」，**能不能听见必须人耳确认** —— 建议先在笔记本喇叭上点面板的「嘶吼」（小喇叭能听见才算过关），再插耳机跑一遍「终局·追逐」。

> 第十轮把嘶吼和追逐音乐又各重做了一遍，本节里的 **96 → 62Hz / 190 → 132Hz / 520 / 1300 / 0.95 / 让开一半** 已被覆盖，请看下一节。

## 第十轮：吼要像人喊，音乐要更凶

第九轮之后又试听了一次，两条反馈：**「嘶吼要重做，我要的是怪物的怒吼类似呃啊啊啊啊啊！！」**、**「追逐的音乐有点平淡，再刺激一点」**。第九轮修的其实是「听不见」（中频不够），但**吼的形状还是错的**：音高从头到尾在往下掉，那是咆哮（growl）的轮廓，人喊「呃啊啊啊」是**先冲上去、再撑住、最后垮下来**。所以这一轮不是加音量，是换形状。

### 嘶吼：从「一声低吼」改成 2.4 秒的长啸（`audio.js` 的 `roar()`）

| 项 | 第九轮 | 第十轮 | 为什么 |
|---|---|---|---|
| 时长 | 1.5 秒 | **2.4 秒** | 1.5 秒怎么响都像「一声」；2.4 秒才像一个人喊到没气 |
| 音高轮廓 | 96 → 62 / 190 → 132（一路下滑） | **150 → 168 → 330 → 352 → 360 → 300 → 196** | 0.26 秒冲到 330Hz 并撑到 1.45 秒 —— 这是「啊」的形状，下滑是「吼」的形状 |
| 嗓子 | 两条 saw，差 0.34 音量 | 两条 saw**只差 12 音分**（同一个人，两条声带） | 差音分才有拍频（人声的「毛」），差分贝只是两条琴 |
| 元音 | 固定 520 / 1300Hz 两个峰 | **三个峰一起滑动**：500→780 / 1500→1150 / 2500→2600，Q 6 / 8 / 9 | /ə/ → /a/ 就是「呃」到「啊」；换滤波器是换音色，滑移才是换元音 |
| 颤动 | 5.5Hz ±22 音分 | 5.5 → **7Hz**，深度 18 → **70 音分** | 越喊越不稳，这是人声和合成器最明显的分界 |
| 破 | 无 | **WaveShaper**（1024 点 tanh，2x 过采样）+ 12Hz 锯齿调幅（深度 0.3） | 软饱和把「正弦感」压成破锣；锯齿调幅比正弦颤更脏 |
| 胸腔 | 无 | saw 165 → 96 → 90Hz 过 240Hz 低通 | 耳机上的「大」；小喇叭上不会糊 |
| 噪 | 750Hz 0.5 + 2.6k→1.7k 0.28 | 750Hz 0.45 + **2.4k→1.4k** 0.3 | 嘶声跟着音高往下走一点，像真的喊哑了 |
| 峰值 | 0.95 × vol | **0.98 × vol**（vol 上限仍是 1.2） | |
| 副作用 | `duckMusic(0.5, 0.85)` | `duckMusic(0.55, 1.2)` → 音乐掉到 **0.45**，1.2 秒后自己涨回来 | 2.4 秒的吼必须把音乐压得更低更久，否则又是「音乐里多了点声音」 |

**长啸和「死寂真空」打架的问题（`game.js`）**：第五轮的节奏是「吼 → 0.73 秒完全无声 → 快跑！」，但 2.4 秒的吼会直接盖掉那 0.73 秒。所以新加了 `cutRoar(fade = 0.12)`（`audio.js`）：记下正在响的那条长啸的包络与要停的振荡器，`cancelScheduledValues()` 后指数淡出到 0.0001 —— **淡出不是硬切**，硬切会「啪」。`beginChase()` 在 `duckAmbient(true)` 之前调 `cutRoar(0.18)`，于是节奏还是「吼 → 死寂 → 快跑！」。

追逐里的重吼冷却从 4.5 秒加到 **6.0 秒**：冷却必须比长啸本身长，否则会变成一条接一条的「啊啊啊」。

`roar(vol, pan)` 的签名没变，四处调用点（`beginFinale()` 0.95、追逐 0.6–1.05、`lose()` 1.1、`devtools.js` 试听 1）都不用改。

### 追逐音乐：从八层到十二层，167 → 200bpm（`chasemusic.js`）

| 项 | 第九轮 | 第十轮 |
|---|---|---|
| 拍长 | 0.40 → 0.32 秒（150 → 187bpm） | **0.36 → 0.30 秒（167 → 200bpm）**，压力拉满时鼓距 0.60 秒 |
| 层数 | 8 层 | **12 层**：低鼓 / **二次鼓（95→58Hz，补第 3 拍的空）** / 金属敲 / **军鼓（1.9kHz 带通，压力 0.25 起）** / **踩镲（7kHz 高通，正反拍都打）** / **低音泵（55Hz 过 260Hz 低通，挂反拍）** / 不谐簇 / **固定音型（174.6/185/146.8Hz，1.15kHz 带通 Q3，压力 0.45 起）** / **撞击（3k 宽带 + 174.6Hz 一记闷响，每 8 拍句头）** / 上升音 / 颤弓 / 轰鸣 |
| 不谐簇最亮 | 1900Hz | **2600Hz**（压力拉满时），失谐 ±8 → **±24 音分** |
| 颤弓 | 深度 0.045 | **0.07 → 0.11**（越近抖得越狠） |
| 不谐簇层 / 轰鸣 | 0.07 / 0.06 | **0.1 / 0.14** |
| 上升音 | 噪声 0.20 | 噪声 **0.26** + 一条 saw 180→720Hz 从 600→2400Hz 扫上去 |

一句话：原来只有「咚……咚……」和一层嗡，现在正拍有低鼓、反拍有泵、2/4 拍有军鼓和金属、每个句头有撞击、全程有踩镲提供密度 —— 小喇叭上也不再是「一片糊」。

### 为什么这些数（`_tools/roar_band.py`）

和第九轮同一个模型（RBJ 公式算 `|H(f)|²`，锯齿谐波 + 噪声谱加权），加了第十轮的三条 `formant()` 路径与胸腔：

| | 第八轮（闷响） | 第九轮（下滑低吼） | 第十轮（长啸） |
|---|---|---|---|
| 总能量 | 0.028 | 0.123 | **0.742（比第九轮 +7.8dB）** |
| 300-3000Hz 占比 | 84% | 48.6% | **84.0%** |
| <300Hz 占比 | 14% | 49.6% | **15.1%** |

第十轮的中高频占比回到了第八轮的水平，但**能量来源完全不同**：第八轮那 84% 是一条 420Hz 的细线（68Hz 基频被 Q5 带通滤掉了，所以像气声），第十轮是 352Hz 基频的第 1~8 次谐波成片通过 780/1150/2600 三条共振峰。模型没算 tanh 饱和（它只会把能量再往上推），所以这个数是保守值。

### 验证

- `node --check`：`src/audio.js`、`src/chasemusic.js`、`src/game.js`、`_probe/fakeaudio.mjs`、`_probe/chasemusic.mjs` 全通过。
- `_probe/chasemusic.mjs` 扩到 **110 多条断言**，全部 exit 0：新增两层鼓/军鼓/踩镲/低音泵/固定音型/撞击的落拍与压力门槛（含「压力 0.2 时军鼓和固定音型不进来，但踩镲和二次鼓已经在推」）、颤弓深度 0.07→0.11、以及嘶吼的一整套形状（起音 150Hz、峰值 360Hz、落回 196Hz、2.4 秒、第二条嗓子 +12 音分、三个共振峰 500/1500/2500 → 780/1150/2600 与 Q 值、颤音 18→70 音分挂两条 detune、胸腔 165→96→90、tanh 曲线 1024 点端点 ±1 与 2x 过采样、12Hz 调幅、750/2400→1400 噪声、`cutRoar` 的 cancel + 指数淡出、vol=0 不建节点、上限 1.2）。
- **耳朵仍然是唯一的判据**：Dev 面板 →「音频试听」→ `嘶吼` 先在小喇叭上听（要听出「呃——啊——」的两段，而不是一声闷响），再插耳机听胸腔。

## 第十一轮：吼和追逐曲都换成真人录音（CC0）

第十轮把合成做到十二层，听感上仍然是「合成的」。你的判词是**「感觉自己合成出来的质量太差了，咆哮和追逐音乐都看看有没有合适的」**，方向因此改成**替换**而不是继续调参数：**吼声和追逐曲都换成网上的 CC0 真录音，合成版降级成加载失败时的兜底**。合成器再怎么调也调不出真嗓子里的那条气流和那点不可控，这不是参数量的问题。

### 吼声：采样 + 一条很短的信号链（`audio.js`）

`ROAR_SAMPLES` 是一张三选一的表，`loadSamples()` 在 `unlock()` 里**并行 fetch 后 decode**（不 await —— 网络慢不能拖住开局）。每个素材在解码后现场量两件事：**起音位置**（扫 `|x| > 0.02`，跳过文件头的静音，不然每次吼都晚半拍）和**峰值**（做响度归一化，三个素材音量不一样大）。

播放链只有四段，每一段都有理由：

| 环节 | 参数 | 为什么 |
|---|---|---|
| 变调 | `playbackRate = 0.9` | 降两个半音。真人的尖叫降调后立刻「不像人」，往怪物的方向靠 |
| 高通 | 60 Hz，Q 0.7 | 掐掉录音里的房间嗡和呼吸 |
| 饱和 | `screamCurve(1.8)`，2x 过采样 | 轻饱和只加「扎」，k 取 1.8 —— 再大就把素材本来的破音磨平了 |
| 包络 | 15 ms 起、撑到 72%、指数收到 2.6 s | 素材是 3.8–10.4 秒的完整表演，我们只要那一声；硬切会「啪」 |
| 归一化 | 按峰值推到 0.95 × vol | 三个素材原始响度差 6 dB 以上，不归一化 A/B 就不公平 |

`duckMusic(0.6, 1.1)` 保留：采样吼声同样把配乐压到 40%，1.1 秒后自己涨回来。`setRoarSample(i)` 换的是 A/B/C，追逐里三次重吼的点还是由 `game.js` 的 6 秒冷却控制。

### 追逐曲：成品曲当「床」，节拍层整体让位（`chasemusic.js`）

关键取舍是**不能让两套鼓抢拍**，所以给成品曲加了一条 `bed` 路线，走它的时候第十二层的合成节拍器**整个不启动**（`scheduleBeat()` 直接 return）：

| 项 | 合成版（第十轮） | 成品曲床（本轮） |
|---|---|---|
| 层数 | 12 层实时合成，200 BPM | 0 层合成 + 1 条循环 BufferSource |
| 压力如何体现 | 加层、提速、开亮度 | **低通 900 → 6000 Hz**、音量 0.42 → 0.62（`CHASE_BED`） |
| 能不能听出「近了」 | 层数变多 | 声音从门后闷着变成贴脸亮着，同一个机制换了载体 |
| 每帧开销 | 排节拍、建节点 | 0 个新节点（探针数过：60 帧 0 节点） |

两首都是 `loop = true`。76.8 秒 / 109.7 秒对 15–25 秒的追逐段来说，一局根本走不到接缝。`setBed()` 支持**追逐中途换曲**（停旧源、重排新源、顺手把压力推 0.01 骗过节流的 2% 门槛），所以 Dev 面板随时可以 A/B。

### 怎么试听（这一次必须由你的耳朵决定）

`Ctrl+Shift+D` →「音频试听」现在是 6 个按钮：`吼 A 人声` / `吼 B 怪物` / `吼 C 太空` / `追逐 A 恶魔` / `追逐 B 追逐` / `停止试听`。点过之后右上角提示会写出**正在放的是哪个素材**，解码失败会直接说失败——不会静默。

建议顺序：先在**小喇叭**上过一遍三段吼（要能听出「啊啊啊」的嗓子，不是低频轰），再插耳机听胸腔和气流；追逐曲按空格跑一次终局，听**压力拉满时低通开到 6 kHz**那一下是不是比合成版更有冲击。

- **合成版一行没删**。`roar()` 先看有没有采样，没有就走第十轮那条十二层链路；`start()` 里没 bed 就建 12 层合成。所以：断网、`file://` 直接双击 `index.html`（fetch 会被 CORS 挡）、素材被删——都只是**退回合成版**，不会哑。
- `node --check`：`src/audio.js`、`src/chasemusic.js`、`src/devtools.js`、`src/game.js`、`server.js` 全通过；`_probe/` 下 15 个探针全部 exit 0。
- `_probe/chasemusic.mjs` 当时 **90 条断言**（第十二轮重数 **175 条**、第十三轮 **180 条**，见下一节），新增 §6 采样路线一整节：三条吼两个床都加载进来、起音偏移 0.285 s 被测出来、峰值 0.45 归一化到 1.90、`playbackRate 0.9` 与只截 2.34 s（缓冲秒数要乘 0.9）、床 `loop === true` 且**不建不谐簇**、压力 1 时 6000 Hz / 0.62、床模式下 60 帧**零新节点**、`setChaseBed` 中途换曲、`stop()` 拆干净、以及**素材为空时 `roar()` 真的退回合成长啸**。
- HTTP 复核：8 个 URL 全 200，`Content-Length` 与磁盘字节数逐一相符（`server.js` 顺手补了 `.ogg` 的 MIME，下次重启服务生效）。

### 结局：五个候选一个都没留下

你听完的判词是**「这几个素材都有点一般，我要怪物恐怖的嘶吼和紧张压抑的追逐音乐，这几个都不太符合」**。所以上面这张表连同那 5 个文件只作为**历史**保留：为什么选错、错在哪，写进了第十二轮的第一节。文件本身还没删（等你点头，按 §10 移到 `_待删/`），但代码里的 `ROAR_SAMPLES` / `CHASE_BEDS` 已经全部指向第十二轮的新素材。

这也是这一轮真正的教训：**「CC0 + 音质不差」不等于「符合题材」**。挑素材时先定题材（drone 还是吉他、野兽还是人），再谈质量和许可。

## 第十二轮：按「音色性格」重选，把改性搬进引擎

判词拆成两句看：**怪物恐怖的嘶吼** + **紧张压抑的追逐音乐**。第十一轮错的地方不是音质，是**题材**：

| 错在哪 | 第十一轮实际选的 | 你要的 |
|---|---|---|
| 追逐曲的**体裁** | 兽人金属吉他（「Bravery Demon」，210 BPM）+ 复古合成器追逐曲（「Chase!」，Synthwave） | 压抑、不旋律、不摇滚 |
| 吼声的**性格** | 人声尖叫 + 太空怪吼 —— 一个是人在喊，一个是电子怪兽 | 非人的、大体型的生物 |

### 先把题材定死，再去搜

- 追逐曲只收 **drone / dark ambient / industrial**：无旋律、有低频、有压迫感。明确排除带鼓组的战斗 BGM、金属、复古合成器——只要出现「旋律动机」，追逐就会变成打游戏打 boss。
- 吼声只收 **大体型非人生物**：爬行类/野兽的嘶咬与低吼。CC0 库里**没有现成的「巨型怪物咆哮」**（那种素材基本都在商业音效包里）。所以这一轮的思路是：**拿一段真实的野兽录音，把「怪物化」交给引擎**——降调、饱和、低八度、调幅抖动、共振峰，全都作用在**真嗓子的共振峰**上，所以它比自己合成出来的更像活物。

### 吼声：一条录音，四档处理链（`ROAR_DESIGNS`，`audio.js`）

素材换了，处理链的**思想**没换（第十一轮那条是对的），但参数化成了四档，Dev 面板里可以直接切，不用改代码：

| 档 | `rate` | 播放中滑到 | 饱和 k | 抖动 | 共振峰 | 低八度 | 气息 | 适合 |
|---|---|---|---|---|---|---|---|---|
| `原声` | 0.90 | —— | 1.8 | 0 | —— | 0 | 0 | 只降两个半音，当对照 |
| `野兽` | 0.82 | ×0.58 | 3.4 | 33 Hz | 620 Hz +7 dB | 0.34 | 0.09 | 体型变大、嗓子在塌 |
| `深渊` | 0.70 | ×0.62 | 4.6 | 19 Hz | 360 Hz +7 dB | 0.55 | 0.13 | 又慢又低，最「不是活人」 |
| `童声` | 1.16 | —— | 2.2 | 0 | 900 Hz +7 dB | 0 | 0.05 | 反向对照：拉高就变成小孩 |

四条链路共用的骨架：`素材 → 60 Hz 高通（掐房间嗡） → screamCurve 软膝饱和（2x 过采样） → [共振峰 peaking Q1.1 +7 dB] → [调幅增益 × 0.38 ← 抖动振荡器] → 包络 → 声像 → 总线`。三个附加层各自独立：**低八度**是同一段素材再开一个源、半速、过 150–220 Hz 低通（真低频，不是合成 sub）；**气息**是白噪声过 1.4 kHz/Q0.9 带通，并且**挂在抖动增益的下游、自带一条更短的包络**（见下一节，这条以前是个 bug 级的听感问题）；**抖动**是 19–33 Hz 的正弦接到增益参数上（真调幅，不是空接，探针专门验了这件事）。

`ROAR_SAMPLES` 里每条素材带一个 `design` 推荐档（沙虫 1、野兽 1、海怪 2），换素材时自动切过去——沙虫本来就很低，再压会糊成泥。

### 第十三轮修正：那层「嘶嘶底噪」是从哪来的

你听完问「为什么吼声会有嘶嘶的底噪」。答案是：**它不在素材里，是引擎叠上去的**。`_tools/roar_hiss.py` 把 `roar-sandworm.wav`（吼 A，也是默认档）拆开数了一遍——纯数组计算，不靠耳朵：

| 频段 | 0–100 | 100–300 | 300–800 | 800–1.5k | 1.5k–3k | 3k–6k | >6k |
|---|---|---|---|---|---|---|---|
| 能量占比 | 67.90 % | 24.91 % | 7.11 % | **0.087 %** | 0.0007 % | 0.0001 % | ≈0 |

频谱质心 **105 Hz**，峰值 RMS −11.8 dBFS，自身底噪 −44.1 dBFS（SNR 32.3 dB），而底噪里 >2 kHz 的分量只有 **0.0091 %**。结论很硬：**这条录音 800 Hz 以上基本是空的**，它是一个纯粹的低频轰鸣，不是「嗓子」。所以吼 A 里凡是嘶嘶的部分，**100 % 是引擎生成的**。

三笔账：

1. **气流层本身太响、太宽**：全幅白噪 → 带通 1600 Hz / Q0.6（通带近 3 kHz，等于在 300–3000 Hz 铺了一整条毯子）→ ×0.16。实测（进入主包络之前）**−28.7 dBFS**，而主声在那个频段几乎为零，它就是唯一的高频。
2. **它还是静止的**：原来直接挂主包络，不随 33/19 Hz 的喉部抖动起伏，尾巴也不收（跟主声同一条包络，72 % 之后才降）。调幅波谷里主声掉到 24 %、白噪一动不动——耳朵立刻把它判成「底噪」而不是「喘气」。
3. **饱和曲线把小信号整体抬起来**：`tanh(kx)/tanh(k)` 在 x→0 处的斜率是 `k/tanh(k)`，k=3.4 就是 3.4 倍。换算成相对提升：**k=3.4 时 +7.7 dB、k=4.6 时 +10.2 dB**。沙虫这条本来没高频所以听不出来，但 B/C 两条 mp3 有房间噪声，被抬 8–10 dB 之后就成了背景那层沙沙声。

修正都在 `src/audio.js`，**不动听感取向，只去噪声**：

| 项 | 之前 | 现在 | 实测变化 |
|---|---|---|---|
| 气流带通 | 1600 Hz / Q0.6 | 1400 Hz / Q0.9 | −2.0 dB（通带收窄） |
| 气流电平 | 0.16 / 0.26 / 0.10 | 0.09 / 0.13 / 0.05 | 野兽 −28.7 → **−39.1 dBFS**；深渊 −24.5 → **−36.0 dBFS**（同为包络之前） |
| 气流走向 | 直接挂包络 | 挂到抖动增益下游（`amNode`） | 随 33/19 Hz 起伏，变成「喘息」 |
| 气流包络 | 和主声同一条 | 自己一条：60 ms 起、50 % 后收、78 % 归零 | 尾巴不再挂一层白噪 |
| 饱和曲线 | `tanh(kx)/tanh(k)` | 软膝：\|x\| ≤ 0.35 线性、≥ 0.9 才满饱和 | 底噪相对提升 +7.7/+10.2 dB → **−2.2/−2.3 dB** |

`|x| = 1` 处曲线仍然输出 1，所以**峰值、音量归一化、`peak` 那套代码一个数都没改**；中段（|x| ≈ 0.5）仍被顶到 1.16 倍，破音还在，只是不再靠抬底噪来换。

### 追逐曲：整体降一个半音 + 低八度垫底（`CHASE_BED`）

床的机制沿用第十一轮（一条循环 BufferSource，压力只做低通和音量），这轮多了两件事：

| 项 | 值 | 为什么 |
|---|---|---|
| `rate` | 0.94 | 整体慢 6%（约一个半音）。drone 的「慢」会把紧张感往下压，而追逐只有 15–25 秒，降速带来的「音高变了」不会被察觉 |
| `subLevel` | 0.42 | 同一段素材再开一个 0.47 速的源，只留 150 Hz 以下，垫一层真低频 |
| `cutoffLow → cutoffHigh` | 900 → 6000 Hz | 压力从「隔着一道门」到「贴脸」 |
| `levelLow → levelHigh` | 0.42 → 0.62 | 只是明暗的补充 |

低八度垫底是这一轮的关键：两条 drone 都偏中频，靠 EQ 提低频会闷成一片，而**把整段降八度播放再切掉高频**得到的是有内容的低频，不是一根嗡嗡的低音管。

### 怎么试听（这一步只能靠耳朵）

`Ctrl+Shift+D` →「音频试听」现在是 `吼 A 巨兽沙虫` / `吼 B 野兽嘶咬` / `吼 C 海怪` / `追逐 A 张力脉冲` / `追逐 B 工业低鸣` / `停止试听`；下面一排 `原声 / 野兽 / 深渊 / 童声` 是**同一条录音只换处理链**，不换素材。

建议顺序：先按 `吼 A` 听「是不是一个有体积的东西在叫」，再切 `深渊` 和 `原声` 对比——差别只该在**体型和嗓子塌不塌**，一旦听出电子味就说明压过头了；然后按空格跑一次终局，听压力拉满、低通开到 6 kHz 那一下会不会真的「贴到脸上」。
