## 2. 硬约束：为什么不能做"真隧道"

这是本方案最重要的判断，先说清楚免得做完发现不对：

| 事实 | 数值 | 出处 |
|---|---|---|
| 前墙血肉面 | `z = -5.99` | `anomalies.js:1369`（`zMin + 0.01`，`zMin = -6`） |
| 教室实墙内表面 | `z = -6.00`，厚 0.15 | `level.js:801` 一带 |
| **真实可用纵深** | **约 8cm** | 两者之差 |
| 现有三层条带的 z | `-5.92`（翻边）/`-5.91`（中层）/`-5.89`（内核） | `anomalies.js` 中 `addBand(...)` 的 `offZ` |
| 现有条带的几何形状 | **实心带**，且越靠中心越靠前 | 同上 |

两个后果：

1. **越靠中心越靠前** → 任何"往里退"的内容都会被内核带挡住，看不见。
2. **实心带铺满整个裂缝轮廓** → 想让脸"镶嵌进去"，只能把整条带改成**环形**，否则脸只能贴在最前面（= 突出墙面 10cm）。

所以：

- ❌ **不做**几十厘米的真隧道（会朝教室内突出 ~0.4m，直接违反"不能突出墙面"）。
- ❌ **不**在 `level.js` 里给实墙开洞（改动跨文件、易出新问题，收益仅多 7cm）。
- ✅ 做 **8cm 的真凹陷**（把 8cm 全部用满），"巨大感"靠三件事堆出来：
  1. **开口大**：约 0.7m 宽 × 2m 高，脸比开口更宽（只露出一条）→ 暗示后面还有更大体积；
  2. **脸极暗**：只有 2~4 级色阶，轮廓几乎溶进黑；
  3. **眼睛小而极亮**：小 + 亮 = 远 + 大，这是标准的"巨大远处物体"视觉线索。

## 4. 分层实施步骤

每步独立可验证，任一步不满意可以只回退该步。

### 步骤 1：挖开口 —— 三层实心带改环形

- 位置：`anomalies.js` 的 `addBand()` 之后（≈1563 行）新增 `addRing(left, right, gIn, gOut, offZ, offY, mat)`：对每一行取 `cz`（左右中点），生成**左右两条** ribbon（`gOut→gIn`），中间留空。
- 替换 4 处 `addBand` 调用（前墙臂 ×3、天花板臂 ×3、转角补片 ×3 → 其中两臂改 `addRing`，**转角补片保持 `addBand` 填实**，那块是接缝，挖空会露缝）。
- 系数：`1.05→1.85`、`0.65→1.05`、`0.34→0.65`，z 分别为 `-5.920 / -5.910 / -5.900`。
- **风险**：裂缝观感会变（中心不再是一条实心黑带，而是黑洞）。用近黑补掉，理论上看不出差别。**这是本方案唯一会动到"你已经认可的那版裂缝"的地方**，所以放在第一步做完先给你看一眼。

### 步骤 2：深渊 + 背板

- 新增 3 级台阶环（复用 `addRing`，材质 `0x140305 / 0x0a0203 / 0x040001`，`fog:false`）+ 背板（`ribbonGeometry` 填满或 `PlaneGeometry` 椭圆，`0x010000`）。
- 全部挂在一个 `eyeCave = new THREE.Group()` 里，方便整体开关/整体动画。

### 步骤 3：黑色巨脸

- 用现有 `addSphere` / `addBox` 组合（`anomalies.js:46-60` 已有）：颅顶球（压扁）、眉弓（细长盒，微前凸 1cm）、鼻梁（楔形盒）、颧骨（两个小球）、下颌（梯形盒）。
- 材质：`MeshBasicMaterial` + **顶点色**做一层"上方略亮、下方更黑"的烘焙渐变，色阶范围 `0x030202 … 0x0d0809`；**不用 `MeshStandardMaterial`**（凹槽里根本没光照到，且会让红环境光染出偏色）。
- 全部顶点必须满足 `z ≤ -5.945`（构建完用脚本断言，见 §7）。
- 目标观感：**正常情况下几乎看不见，只有眼睛亮着**；灯灭（`flickerDark`）时才隐约浮出一点轮廓。

### 步骤 4：双眼

- 眼球：`SphereGeometry(0.065, 16, 12)`，`MeshBasicMaterial({ color: 0xff2030, toneMapped: false })`（`toneMapped:false` 是关键，否则 ACES 会把红压灰——`m2.js:158-159` 已有注释说明这点）。
- 光晕：同心 `SphereGeometry(0.156)`，`transparent, opacity 0.22, blending: AdditiveBlending, depthWrite: false, toneMapped: false`。
- 可选点光：`PointLight(0xff2233, 1.2, 3.0, 2)` 放在两眼之间。**注意代价**：新增一盏点光源会让全场景材质重新编译一次（`NUM_POINT_LIGHTS` 变化），第 5 关生成瞬间可能卡一下。**默认不加**，先用加性光晕；你觉得不够亮我再加。
- 待机动画（照抄 `docs/level5_plan.md:160-163`）：
  - 心跳缩放 `1 + 0.06 * sin(t * 2.4)`
  - 瞳孔（内层小黑球）`0.85 + 0.12 * sin(t * 3.1 + 1.1)`
  - 光晕呼吸 `0.18 + 0.06 * sin(t * 2.3)`
  - 缓慢扫视（`docs/level5_v3_plan.md:82` 提到的 `lookX/lookY`）：两眼整体在 `±0.012` 内极慢平移，避免"死盯"
  - `flickerDark` 时整体亮度 ×1.35

### 步骤 5：拍照判定改为"必须命中眼睛"

- 新增命中球：`new THREE.Mesh(new THREE.SphereGeometry(0.55, 8, 6), new THREE.MeshBasicMaterial())`，`visible = false`，放在 `(0, 2.45, -5.94)`。
- `tagAnomaly(eyeHitbox, 5, 'flesh-eyes')`。
- **删掉** `anomalies.js:1819` 的 `tagAnomaly(group, 5, 'flesh-crack')` 和 `anomalies.js:2021` 的 `tag(group, 5, 'flesh-wall')`，改为只设 `group.name = 'anomaly-flesh-wall'`（保留调试可读性，不挂 `anomalyLevel`）。
- 效果：瞄墙面 → `aim()` 返回 `none` → 拍照失败（提示"没拍到"）；瞄眼睛（±0.55m 内）→ 成功。`hud.setAimHot` 会跟着亮，玩家能学会该瞄哪儿。

### 步骤 6：瞄准点与站位

- `level.js:411` 目前只支持 `(0, aimY, 0)`，拿不到 z。改为：
  ```js
  const local = anomaly.aim
    ? new THREE.Vector3(anomaly.aim.x, anomaly.aim.y, anomaly.aim.z)
    : new THREE.Vector3(0, anomaly.aimY ?? 0, 0);
  return anomaly.group.localToWorld(local);
  ```
  向后兼容（其他 4 关不传 `aim` 就走老路径）。
- `createFleshWall()` 返回值加 `aim: { x: 0, y: 2.45, z: -5.95 }`。
- **一个副作用要你知道**：`CONFIG.photoRange = 8.5`（`config.js:13`）。现在 `aimY: 3.15` 指向房间正中天花板，站在 `stand(0, 4.2)` 距离只有 4.5m，随便拍就能过。改成眼睛后，从 `(0,1.62,4.2)` 到眼睛有 **10.2m**，超出 8.5m → **玩家必须往前走大约 1.7m 才能拍到**。
  我认为这是好事（必须逼近裂口），所以建议**不动 `photoRange`**，只把 `stand` 更新成 `{ x: 0, z: 2.0 }` 备案（目前 `stand` 只有 `demo.js` 在用）。

### 步骤 7：拍后淡出（接在已有回调上）

- `onPhoto()` 里除现有的血雾加深外，启动 `eyeFade = 0`。
- `update()` 每帧推进 `eyeFade`（1.6 秒走完），然后：
  - 眼球 `color.setScalar(1 - fade)`（亮度线性降到 0）
  - 整体 `scale = 1 - 0.55 * fade`
  - `position.z = lerp(-5.972, -5.990, fade)`（往深处退 1.8cm）
  - 光晕 `opacity = 0.22 * (1 - fade)`
  - 瞳孔 `scale *= (1 - 0.4 * fade)`
  - `fade ≥ 1` 后 `eyeCave.visible = false`（彻底消失，省 draw call）
- 时间线对齐：低吼是 1.2s / 0.9s 两层 + 2 个 tone，颤抖 2.0s，眼睛 1.6s → 眼睛比颤抖早一点消失在黑暗里，符合"淡去"。

| 新增 1 盏点光的着色器重编译 | 中 | 同上 | 走路时 |
| 首次渲染 1150 个网格 | 小 | 同上 | 走路时 |

所以你的方案不只是"躲开那一下卡顿"，它一次把**四笔开销**全挪到了玩家走路的时候，同时顺手修掉了"进屋才变血肉"的穿帮。方向完全正确。

### 10.2 我再补一层：预建 + 异步编译，把卡顿也消掉

只把 `spawnUpTo(5)` 挪到走廊，卡顿只是**搬家**，走路时会掉一下帧。要真正消掉，还需要两件事：

**① `level.prewarm()`：在玩家还在菜单/第 1 关时就把血肉教室建好，但不挂进场景**

```js
// level.js，约 12 行
prewarm(level) {
  if (!this.prewarmed) this.prewarmed = new Map();
  if (this.prewarmed.has(level)) return;
  if (this.anomalies.some((a) => a.level === level)) return;
  this.prewarmed.set(level, createAnomaly(level));   // 只建，不入 scene
}
// spawnUpTo 里优先取预建的那份
let anomaly = this.prewarmed?.get(level);
if (anomaly) this.prewarmed.delete(level);
else anomaly = createAnomaly(level);
// clearAnomalies 里也要把 prewarmed 一并 dispose，否则重开会泄漏
```
在 `main.js` 启动后用 `requestIdleCallback` 调一次 `level.prewarm(5)`——玩家还在主菜单，卡一下完全看不见。

**② 把 `onSceneChanged` 接上 `compileAsync`（代码里本来就想做，但一直没赋值）**

`level.js:149-151` 和 `396-397` 有两处注释写着"新异常带着新材质，先让渲染器编译，避免玩家第一次看到它时掉帧"，调用的是 `this.onSceneChanged?.()` —— 但全项目**没有任何地方给 `onSceneChanged` 赋值**，所以这个钩子一直是空的（`?.()` 静默跳过）。而 vendored 的 three.js **有 `compileAsync`**（`vendor/three.module.js:29897`，走 `KHR_parallel_shader_compile`）：

```js
// main.js，3 行
level.onSceneChanged = () => { renderer.compileAsync(scene, camera).catch(() => {}); };
```
这样新增点光触发的着色器编译是**异步**的，不阻塞主线程。

### 10.3 触发点（采纳你的 "走廊途中"）

放在 `game.js:524 enterCorridor()` 末尾，**只在离开第 4 关时预建第 5 关**：

```js
// 走出教室后就把第 5 关的血肉教室挂进场景：
// 玩家在走廊里回头/透过窗看到的就是血肉模式，而不是进屋才变。

```

为什么是这里：`enterCorridor()` 在玩家 `z > 7.35`（已出门 1.35m）时触发，此刻他背对教室在往前走，**变身的瞬间照不到**；等他一回头，看到的就是成品。而 `beginLevel(5)` 里的 `spawnUpTo(5)` 因为 `anomalies.some(...)` 已存在会自动跳过（`level.js:389` 本来就幂等），所以**不会重复创建**。

只预建第 5 关、不动 2~4 关：那三关的异常都是小物件，2~4 关进屋时"多出来一个东西"本来就是玩法节奏，提前放好反而提前剧透。

### 10.4 后墙必须挖窗洞（已确认：保留窗口可透过）

**问题**：`addDoorWall()` 现在给后墙铺的是整片 9.2m × 3.2m、只留门洞，而 `level.js:861` 的后墙是大窗洞。所以血肉墙从教室内侧把整排窗糊死了，走廊里透过玻璃只能看到一块血肉板。

**已确认做法**：后墙按"横带 + 竖缝"分解，把 6 个窗洞和门洞都留空。

窗位从 `level.js:868-891` 精确推导（`jambW = 0.12` → `outer = 0.92`；`count=3`、`winW=1.9`、`sill=0.95`、`winTop=2.28`、`pier=0.845`）：

| 窗 | x 区间 | | 窗 | x 区间 |
|---|---|---|---|---|
| 1 | `-9.155 … -7.255` | | 4 | `1.765 … 3.665` |
| 2 | `-6.410 … -4.510` | | 5 | `4.510 … 6.410` |
| 3 | `-3.665 … -1.765` | | 6 | `7.255 … 9.155` |

全部 `y ∈ [0.95, 2.28]`；门洞 `x ∈ [-0.8, 0.8]`、`y ∈ [0, 2.46]`。

**分解方案**（按 y 切 4 条横带，每条带内按 x 扣掉缺口）：

| 横带 | y 区间 | 缺口 | 实心分片数 |
|---|---|---|---|
| 1 | `0 … 0.95` | 门 | 2 |
| 2 | `0.95 … 2.28` | 门 + 6 窗 | 8 |
| 3 | `2.28 … 2.46` | 门 | 2 |
| 4 | `2.46 … 3.20` | 无 | 1 |

共 **13 块**。原来那个 20m 宽的"门上方"块和 `overMesh` 门楣条都被这套分解取代，一并删掉（`overMesh` 本来就是个共面闪变源）。

**顺便解决贴图的两件事**：13 块如果各 clone 一份纹理 = 13 张 512² 上传，而且图案在缝处会错位。改成：

- **只建一份**后墙专用纹理（`repeat` 设成 `(1,1)`），13 块共用；
- 把 UV **按世界坐标烘进几何体**：`u = 0.3 * x`、`v = 1.40625 * y`。

好处是三重的：① 只多 1 张纹理；② 图案跨缝连续（甚至跨窗洞也连续）；③ 流动动画只需要动一份 `offset`。
